# Final Experiment — Dual-Representation Sentiment Ensemble (DRSE)

Manglish (Malay-English code-mixed) tweet sentiment classification into
**negative / neutral / positive**, using a two-branch ensemble:

- **Branch A** — CNN head over a BERT encoder (`bert-base-cased`), BERT tokenizer
- **Branch B** — GRU over Keras word-tokenised sequences

The two branches are fused by a weighted sum of (temperature-scaled) logits:
`alpha * CNN + (1 - alpha) * GRU`.

## Four things to know before citing any number

### 0. The "BERT baselines" contain no BERT

`Baseline experiment/BERT/BERT + *.py` import `BertTokenizer` and nothing else —
line 116 of each is `nn.Embedding(vocab_size, 128)`, a randomly-initialised lookup
table. They compare **tokenizers** (WordPiece vs Keras word), not encoders. The
scripts' own headers say so (`# BERT TOKENIZER + CNN`); only the figures
overclaimed. Label them **BERT Tokenizer + X**.

Their numbers also have no on-disk provenance — the export blocks are commented
out, so the values exist only as literals typed into the chart scripts.

`Baseline experiment/canonical rerun/` re-runs all eight correctly on the canonical
split and writes every number to disk. See `STAGE1_BASELINE_PLAN.md` for the full
audit.

### 1. There are two eras, split by the leakage fix

Everything in this folder predates or postdates one correction, and the numbers
are not comparable across it.

**Pre-fix (leaky).** Branch checkpoints were trained by scripts that each called
their own `train_test_split(..., test_size=0.15)`. The ensemble scripts then
re-split the *same* dataset independently (`test_size=0.4` → 60/20/10/10). The
two partitions are unrelated, so roughly 85% of the ensemble's "test" rows had
already been seen during branch training. This is what produced the
**~0.86 accuracy** figures.

**Post-fix (canonical).** `redo/split_generator.py` writes one shared
partition — `redo/canonical_dataset.csv` + `redo/splits.npz`
(train 5901 / val 1967 / cal 983 / test 984, seed 42, stratified) — and asserts
zero pairwise overlap. Every script from this point loads that file instead of
splitting. Honest accuracy is **~0.63–0.67**.

> **`Mubin Master Finalize experiment.xlsx` still contains the pre-fix ~0.86
> numbers** in its *Performance optimized ensembled* and *ablation study
> performance* sheets. Those are leakage artefacts, not results. The
> `04 Legacy (do not cite)` sheet of `RESULTS_CONSOLIDATED.xlsx` lists every
> affected row.

### 2. `_smoketest_sandbox_DO_NOT_USE/` is a sandbox, not results

This folder was called `outputs/` until 2026-08-20. Its
`_smoketest_harness.py` fakes TensorFlow, fakes the BERT weights with a tiny
randomly-initialised stand-in, and shrinks the search budget so the V3 scripts
can be proven to run end-to-end without a GPU. Its
`redo/canonical_dataset.csv` is **420 synthetic rows, 2 columns** — not the real
9,835-row dataset.

The hazard: it mirrors the real directory layout exactly, including
`…/tuned GRU keras model/V3/gru_best.pt`. Those checkpoints and workbooks are
fakes sitting at real-looking paths. Do not copy anything out of it.

The three real V3 scripts that used to live there have been moved into the main
tree; they resolve paths from the working directory, so they run unchanged from
the experiment root.

### 3. `improvement/v2/` is an unfinished smoke run

`step4_tune_branches.py` (XLM-R + tunable GRU) and `step5_export_logits_v2.py`
were only ever run with `--smoke`, i.e. 1 trial, 1 epoch. Both
`v2/gru/gru_best_params.json` and `v2/xlmr/xlmr_best_params.json` carry
`"smoke": true`, and the script itself prints *"results meaningless. Re-run
without --smoke."* The 1.1 GB `v2/xlmr/xlmr_best.pt` is a real XLM-R
architecture trained for one epoch — a placeholder, not a result.

Steps 1–3 are complete and real. Steps 4–5 are not.

## Results (leakage-safe only, canonical 984-row test set)

| Model | Accuracy | Macro-F1 | Branch checkpoints |
| --- | --- | --- | --- |
| **Tuned ensemble V3** (α=0.55, T_cnn=0.75, T_gru=1.25) | **0.6728** | **0.6664** | V3 tuned |
| Base fusion on V3 branches (α=0.6, T=1) | 0.6646 | 0.6586 | V3 tuned |
| S2 stacker (val+cal) | 0.6494 | 0.6440 | V2 |
| S1 stacker (cal only) — *improvement headline* | 0.6443 | 0.6387 | V2 |
| CNN+BERT branch alone | 0.6382 | 0.6309 | V3 tuned |
| M2 alpha + class bias | 0.6413 | 0.6308 | V2 |
| Base ensemble V2 (α=0.6, no temperature) | 0.6341 | 0.6218 | V2 |
| Optimised V2 (alpha grid + temperature) | 0.6250 | 0.6142 | V2 |
| GRU branch alone | 0.5732 | 0.5459 | V2 |

Two distinct branch generations are in play, and rows are only comparable
within a generation:

- **V2 branches** — `…/epoch CNN BERT model/epoch Version 2/cnn_bert_best.pt`
  and `…/epoch GRU keras model/epoch Version 2/gru_best.pt`. Used by stages 4, 5
  and 6 (including all of `improvement/`).
- **V3 tuned branches** — `…/tuned CNN BERT model/V3/` and
  `…/tuned GRU keras model/V3/`, from a 15-trial / 25-trial random search.
  Used by stage 7 only.

This is why "base ensemble" appears twice with different numbers (0.6218 on V2
branches, 0.6586 on V3 branches). Same fusion rule, different branches.

### Where the headroom is

From `improvement/Chapter4_Final_Tables.xlsx` (T4, V2 branches):

| Quantity | Share |
| --- | --- |
| Both branches correct | 0.4299 |
| Only GRU correct | 0.1433 |
| Only CNN-BERT correct | 0.1839 |
| **Neither correct (unreachable by any fusion)** | **0.2429** |
| Oracle accuracy | 0.7571 |
| Best possible weight+bias rule (fitted *on test*) | 0.6539 macro-F1 |

The ceiling for any reweighting of these two V2 branches is ~0.654 macro-F1, and
the base was already at 0.622 — so fusion tuning alone could yield at most ~3
points. The V3 result (0.6664) beats that ceiling only because it *retrained the
branches*, which is the honest conclusion: **branch quality, not fusion weights,
is the binding constraint.**

Neutral-class collapse is the other recurring theme — neutral recall runs
0.4669 (base V2) → 0.6304 (S1 stacker) → 0.6265 (tuned V3), traded against
positive recall (0.7199 → 0.6091 → 0.6580).

## Reproducing the best result

```bash
uv run --with pandas --with openpyxl --with torch --with transformers --with tensorflow python "base essemble model experiment #1 (BERT + CNN & NLP + GRU)/experiment V3 (tuned ensemble model).py"
```

Run from this folder — the script uses relative paths. It needs
`redo/canonical_dataset.csv`, `redo/splits.npz`, and the two V3 checkpoint
directories. It does not retrain; it loads checkpoints, selects the fusion
weight on validation, and touches the test set exactly once.

## Conventions

- Seed 42 everywhere.
- Labels: `negative` / `neutral` / `positive` from column `majority_sent`;
  text from column `comment/tweet`.
- "essemble" is a consistent misspelling of "ensemble" in folder names — kept
  as-is because scripts hardcode these paths.
- Headline metric is **macro-F1** (the classes are imbalanced: 420/257/307 in
  test).
